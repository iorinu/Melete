# Melete V1→V2移行前のバックアップ・復旧準備

状態: 移行前の人間向け準備文書。実ストアのバックアップや移行手順の実行記録ではない。

## 現行状態

- 通常のMeleteアプリはSwiftDataの `MeleteSchemaV1` を使用する。現時点で通常ストアをV2へ移行する実装・実行は確認していない。
- DEBUG時に限り、引数で指定された安全なUIテスト用一時ストアへ、V1または実験的V2を隔離して開く分岐がある。実験的V2は `MeleteMigrationPlan` を使う。この隔離分岐は通常ストアのV2移行を意味しない。
- 本書の作成時点で、実ストアへのアクセス、バックアップ、復元、移行は実施していない。Meleteにユーザー向けバックアップ機能があるとも確認していない。
- 以下は作業を始める前に人間が確認するための準備事項であり、具体的な実ストア操作コマンドではない。

## 実ストアを扱う前の停止点

1. **アプリを完全に終了する。** 作業中にアプリや別のプロセスがストアへ書き込まない状態にする。終了を確認できなければ作業を止める。
2. **実際のstore URLをユーザー本人に確認してもらう。** 実行中の環境で対象ストアの場所を本人が確認し、対象として明示する。推測や固定パスを根拠に選ばない。URLが不明、複数候補がある、または本人が確認できない場合は停止し、ストアを開いたり列挙・探索したりしない。
3. **SQLiteのWALを単独でコピーしない。** SQLiteがWALモードで動作している場合、主データベースファイルだけ、またはWALファイルだけの単純コピーを整合したバックアップとみなさない。整合したスナップショットにはSQLite online backup API等を使う。WALとSHMを個別コピーして代用しない。
4. **新規の別ファイルへバックアップ／復元する。** 復元先は新しく作成する別ファイルとし、既存ファイルを宛先にしない。バックアップおよび復元後にSQLite整合性を確認し、さらに復元先をSwiftDataで開き直してアプリ相当の読み取り確認を行う。確認できない、エラーがある、または対象が想定と異なる場合は停止し、元ストアを変更しない。
5. **追加承認が必要な操作は、操作前に止まる。** 既存ファイルの移動・置換・削除、実データの読み取り・書き込み、通常ストアでのアプリ起動、移行実行などを行う場合は、対象パスと対象データ、操作内容・理由、想定される影響、復元手段を具体的に示し、ユーザーの事前承認を得る。承認がない、対象や復元手段が不明、または説明と実対象が一致しない場合は実行しない。

本書には実ストアを対象とするコマンド例を記載しない。対象URLの確認前に具体的なSQLite操作を案内・実行してはならない。

## 今回の合成V1 SQLiteテストで確認したこと

`MeleteTests/SwiftDataV1BackupSafetyTests.swift` のテストコードが、テスト専用の一時ディレクトリに作る合成V1ストアについて確認する内容は次のとおり。

- 合成データには、任意項目の `nil`、数値の `0`、非ゼロ値と、それらに対応するスナップショットが含まれる。
- backup開始前に合成元ストアのWALが存在し、サイズが0より大きいことを確認する。
- SQLite online backupで元から新規バックアップファイルを作り、整合性を確認する。さらにそのバックアップから別の新規復元ファイルを作り、整合性を確認する。
- 復元ファイルをV1のSwiftDataコンテナで開き、ID、項目順、関連、値、スナップショット等のfixture内容を読み取って照合する。
- 元コンテナを閉じて開き直し、元ストアの内容がバックアップ操作で変わっていないことをfixtureと照合する。
- 別テストでは、存在しない入力元に対する読み取り専用backupが失敗し、入力元・宛先を作成しないことを確認する。

これはコード上の合成fixtureに対するテストであり、実ストアについての結果ではない。

## 未確認事項

今回の確認から、次の事項は結論できない。

- ユーザーの実ストアの場所、状態、WALの有無・内容、バックアップの成否。
- 実アプリでのsave失敗やSwiftData migration失敗の発生時挙動。
- save中・migration中のクラッシュ、およびその後の復旧可否。
- 移行失敗時に実データを保持して復旧できること。
- 復元したストアを通常の本番アプリで起動・利用できること。
- 実ストアの全データ・全関連・全履歴が完全に保持されること。
- ストア特定・終了確認後から操作開始までの競合（TOCTOU）を含む、実環境での安全性。
- V1からV2への実データ移行が可能であること、または移行方式・復旧手順が確立済みであること。

## このテストの適用範囲

上記のfixtureとSQLite backup処理はテストコード内だけのもの。Meleteのプロダクト機能、ユーザー向けバックアップ機能、実ストアを自動保護する機能として実装されたものではない。合成V1のSQLite online backup／別ファイル復元／再open検証を、実ストアでのバックアップ保証や移行成功の証拠として扱わない。
